---
title: Persistent shell sessions
description: Restore agent shell sessions after an SSH disconnect

The client can create persistent shell sessions on an agent. The shell and its
PTY remain alive when the operator's SSH connection is interrupted, allowing a
later connection to continue the same shell, working directory, and running
foreground process.

## Use a session

Run `tealc ssh AGENT --session`. The interactive picker lists running sessions
and a **[NEW]** entry. Choosing **[NEW]** creates and attaches to a shell;
choosing a detached session resumes it. Choosing a session that already has a
writable attachment opens a read-only observer instead.

```sh
tealc ssh AGENT --session
```

Only one writable attachment is allowed for a session. Up to 32 read-only
observers can receive its recent output and live output, but cannot send input
or resize the PTY. Session IDs are generated by the agent and displayed when a
new session is attached.

Persistent sessions are enabled by default. On the agent, use these settings
to disable the feature, observers, or retained output:

```yaml
sessions-enabled: true
session-observers: true
session-history-size: 4194304 # bytes; 0 disables output history
```

The default output history is 4 MiB per session; older output is discarded
first. A shell that exits remains listed for ten minutes, but cannot be
attached again.

While attached, press `Ctrl-g` followed by `d` to detach without terminating
the shell. `Ctrl-g` followed by `Ctrl-d` is also accepted. `Ctrl-D` on its own
and `exit` still terminate the shell itself. If the key after `Ctrl-g` is not
`d` or `Ctrl-d`, the prefix is forwarded normally to the remote application.

Sessions are kept in the agent process. They are terminated when that process
restarts or shuts down; they are not persisted across an agent restart.
